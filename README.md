# CareConnect — Full Stack Development project

A social-impact platform connecting donors and volunteers with old-age homes:
publish requirements, track donations to delivery, manage volunteer
opportunities, and verify organisations — all backed by a real Express +
MongoDB API.

```
CareConnect-FSD-Final/
├── frontend/          React + Vite + Tailwind UI (the live app)
├── backend/           Express + MongoDB API (auth, OTP, donations, admin)
│   ├── src/models/    Mongoose schemas
│   ├── src/controllers/
│   ├── src/routes/
│   ├── src/middleware/
│   ├── src/services/   token, OTP, email/SMS
│   ├── src/config/
│   └── src/scripts/seed.js
├── tests/             jest + supertest integration suite (in-memory Mongo)
├── docs/              API mapping, auth/OTP, DB, env, testing, deployment
├── package.json       test runner (jest, supertest, mongodb-memory-server)
└── README.md
```

## Prerequisites
- Node.js 20.19+ (Node.js 22 LTS or newer recommended)
- MongoDB (local `mongod`, or a free MongoDB Atlas URI)

## Quick start

1. Start MongoDB locally (or use a MongoDB Atlas connection string).
2. In Terminal 1, configure and start the backend:
```bash
cd backend
cp env.example .env
# Edit backend/.env and replace both JWT secrets with independent random strings of 32+ characters.
npm install
npm run seed
npm run dev
```
3. In Terminal 2, configure and start the frontend:
```bash
cd frontend
cp env.example .env
npm install
npm run dev
```
Open the frontend URL (default http://localhost:5173). Register a new account
(the OTP prints in the backend terminal when SMTP is not configured), or log
in with a demo account.

## Run the tests
```bash
cd backend && npm install        # backend runtime deps
cd .. && npm install             # test runner (jest, supertest, mongodb-memory-server)
npm test                         # in-memory MongoDB — no external services needed
```
The included suite is designed to exercise register→verify→login, password reset, role guards, the donation lifecycle, volunteer applications and admin verification. Run it locally before claiming a test pass. See
`docs/TESTING.md` for the full report.

## How the frontend talks to the backend
The frontend API client (`frontend/src/api/careconnect.js`) targets
`VITE_CARECONNECT_API_URL`. All backend routes are under `/api`. The frontend
operations are mapped to the backend routes in `docs/API_MAPPING.md`; runtime
compatibility still needs to be confirmed by running the included tests locally.

## Security
bcrypt password hashing · JWT access + httpOnly refresh cookies · hashed,
single-use time-limited OTP with cooldown + attempt cap · hashed, rotated and
revocable refresh tokens · role-based authorization · auth/OTP rate limits ·
no email enumeration on forgot-password.

## Current functional scope and limitations

- Email verification uses real backend OTP generation and validation. Configure SMTP for delivery; local development prints OTPs in the backend terminal.
- Phone verification is available from Profile. Configure Twilio for SMS delivery; local development prints OTPs in the backend terminal.
- Organisation verification accepts HTTPS document links/references. Direct file uploads are not included.
- Monetary contributions are stored as pledges; there is no payment gateway integration.
- Genuine Wikimedia Commons photographs are loaded from their source URLs. They are not bundled locally; see `docs/IMAGE_ATTRIBUTION.md`.
- The frontend lockfile is included. Backend and root test-runner lockfiles are generated by `npm install` on first setup because the archive environment could not reach the npm registry. Run the build, `npm audit` and integration tests on your Mac before final submission.
