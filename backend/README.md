# CareConnect — Backend (Express + MongoDB)

The single source of truth for CareConnect accounts, donations and operations.
The React frontend talks to this API over a configurable base URL
(`VITE_CARECONNECT_API_URL=http://localhost:5001/api`).

## Stack
Node.js 20.19+, Express, MongoDB (Mongoose), JWT access tokens + httpOnly refresh
cookies, bcrypt password hashing, express-validator, nodemailer email OTP,
optional Twilio SMS OTP.

## Quick start
```bash
cd backend
cp env.example .env          # then edit .env (set MONGODB_URI + JWT secrets)
npm install
npm run seed                 # creates demo accounts + sample data
npm run dev                  # starts API on http://localhost:5001
```

Then from the frontend: set `VITE_CARECONNECT_API_URL=http://localhost:5001/api`
and run the frontend dev server.

## Email / SMS OTP
If `SMTP_HOST` is empty the server logs the OTP to the terminal
(`EMAIL_DEV_LOG=true`) so you can register and verify without a mail provider.
Set real SMTP values for production. Twilio SMS is optional; without it, phone
OTP is also logged to the terminal.

## Structure
```
server.js              entry — connects DB and starts the server
src/app.js             express app + route mounting (/api/*)
src/config/            env + mongoose config
src/models/            Mongoose schemas (User, Organization, Requirement, …)
src/middleware/        auth (protect/authorize), error handling, rate limits
src/services/          token, OTP and messaging (email/SMS) services
src/controllers/       route logic per domain
src/routes/            express routers (mounted under /api)
src/scripts/seed.js    demo data seed
tests/                 jest + supertest integration tests
```

## Scripts
- `npm run dev` — nodemon dev server
- `npm start` — production server
- `npm run seed` — seed demo data
- `npm test` — run integration tests (uses an in-memory MongoDB)

## Security
- Passwords hashed with bcrypt (cost 12).
- Access tokens are short-lived JWTs; refresh tokens are httpOnly, SameSite
  cookies, rotated on every refresh.
- OTPs are hashed, single-use, time-limited, with a resend cooldown and
  attempt cap.
- Role-based authorization on every protected route.
- Rate limiting on auth and OTP endpoints.
- `forgot-password` always returns a generic message (no email enumeration).

The frontend lockfile is included in the project. The backend package lock is generated by the first `npm install` in this directory; this archive was prepared in an offline environment without npm registry access.
